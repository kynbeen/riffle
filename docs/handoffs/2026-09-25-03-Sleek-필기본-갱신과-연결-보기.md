## 내린 결정과 근거

- **필기본 → 필기본은 새 판이 정답(사용자 결정).** 결과 쪽 구조 = 새 판. 새 판에 없는 빈 옛 쪽은 뺀다(화면 `뺀 쪽` 으로 보이고 되돌릴
  수 있다). 손필기가 있는데 새 판에 없는 옛 쪽만 옛 쪽째 남기고 묻는다 — 원칙 7(한 획도 안 버림)이 쪽 구조 일치보다 위.
- **「사라진 쪽」은 묶음 단위로 판정.** 강의록 쪽이 새 판에 있으면 남는 옛 반복 쪽은 합쳐진다 — 사라진 쪽이 아니다.
- **반복 나누기 = 필기 흐름의 상대 위치**(칸 글이 끝나는 높이로 잰 몫이 가장 크게 겹치는 새 쪽, 비슷하면 앞쪽). 사용자가 말한 "상대
  스케일". 쪽 번호 비율은 마지막 쪽이 반만 찬 경우 어긋나서 안 씀.
- **비 Sleek → 필기본은 합집합 유지.** 합집합을 정한 사례(족첵 기출 색인)가 바로 이 방향이다.
- **떨어진 곳의 똑같은 쪽이라도 앞뒤 이웃이 바로 이어져 짝지어졌으면 묻지 않는다**(새 파일이 필기본일 때). 병리 2주차(1) 볼 쪽 4 → 2.
- **칸 손필기: 밑의 글이 같으면 제자리 → 가장 가까운 빈자리 → (사용자 결정) 강의록 빈칸 → 50% 까지 줄이기 → 그때만 묻기.**
- **미리보기와 저장은 같은 함수**로 필기 바이트를 만든다 — 화면과 파일이 어긋날 수 없게(원칙 5).
- **창은 작업 표시줄을 가리지 않는 최대화** — 탐색기에서 파일을 끌어와야 한다.
- **Samsung Notes `.page` 합치기는 레이어에 객체 레코드를 바이트째 덧붙이고 개수만 늘린다.** 획을 다시 쓰지 않는다(원칙 7).

## 미해결 질문 / 블로커

- **푸시 보류(사용자 할 일, 가장 중요).** 옛 Render 서비스 `noteditor` 가 `main` 을 따라 자동 배포된다. Render 대시보드에서 그 서비스의
  배포 가지를 `noteditor-1.2` 로 바꾼 뒤 `git push origin main`. 로그인이 필요해 Claude 가 못 한다. **그 전까지 이 인계와 커밋은 이 PC 에만 있다.**
- **커밋 안 된 세 파일**(`README.md`, `riffle/version.py`, `tests/test_version.py`) — 이번 세션이 만든 것 아님. 커밋할지 사용자 결정 대기.
  이 때문에 **README 에 이번 기능(필기본 갱신·연결 보기·`python -m riffle <파일들>`)을 못 적었다.**
- **로컬 웹 판을 걷을지(사용자 결정 대기).** 추천: 로컬 웹을 걷고 데스크톱(이 PC)·원격 웹(다른 기기) 두 갈래로. PWA 로 일원화하면
  서버를 먼저 띄울 실행기가 남거나(로컬) 필기 파일을 인터넷 서버로 올려야 하고(원격), 파일 경로를 몰라 저장 위치 고르기·폴더 열기·
  파일 받아 열기를 잃는다.
- **Goodnotes 5**(단위 7): 실물 샘플이 없어 미확인. 공개 자료(`cable729/inkterop`)는 스키마 24·25 모두 같은 ZIP 구성을 적는다.
- **태블릿 확인**(단위 8, 사람): 여러 옛 쪽을 합친 Samsung Notes 쪽이 열리고 편집되는지. 쪽마다 따로 저장된 펜 캐시(`.spi`)가 합친
  획을 늦게 반영할 위험 — 미확인. 여백·강의록 빈칸으로 옮긴 획 편집도 미확인.
- 칸 손필기 여백·강의록 빈칸 옮기기는 **합성 파일로만** 확인했다(실제 샘플은 칸 글이 안 바뀌어 모두 제자리).
- Goodnotes 여러 쪽 합치기는 부품 시험만 — 파일 저장까지 끝까지 돌린 시험 없음.
- 데스크톱 창: 복원한 뒤 가장자리를 끌어 크기를 바꿀 수 있는지 미확인. 실제 창 모양은 화면이 잠겨 캡처 못 함(막대는 브라우저로 확인).
- 합치기 창(경우 10)은 분석 기록이 없어 떴는지 기록으로 확인 못 함.

## 다음 단계

1. 사용자: Render 에서 `noteditor` 배포 가지를 `noteditor-1.2` 로 → 알려 주면 `git push origin main`.
2. 사용자: 세 파일 커밋 여부 결정 → 커밋하면 `README.md` 「필기 옮기기」 절에 필기본 갱신·연결 보기, 「데스크톱」 절에 `python -m riffle <파일들>` 을 한 줄씩.
3. 사용자: 로컬 웹 걷기 결정 → 걷는다면 `riffle/local_web.py`·`launch_web.pyw`·`installer/Riffle.iss` 의 로컬 웹 바로가기·
   `Riffle.spec` 의 `RiffleLocalWeb` 빌드·`tests/test_local_web.py`·README 「로컬 웹 앱 실행」 절을 걷고 명세를 쓴다.
4. 사용자: 경우별 창(`python tools/open_cases.py`, 목록은 `--list`)으로 눈 확인 → 저장한 `.sdocx` 를 태블릿에서 열어 모인 쪽·옮긴 칸 손필기 편집 확인(단위 8).

6. 칸 글이 바뀐 자리에 손필기를 쓴 실제 필기본 쌍이 생기면 `tools/check_review_screen.py --notes` 와 저장 결과 그림으로 여백 옮기기를 실측해 명세 변경 이력에 적는다.
