# Riffle 현재 상태

**기준일:** 2026-09-27 (Riffle 1.0.0 — 태그 `v1.0.0`. 설치 파일은 GitHub Release, 웹은 <https://riffle-9rnx.onrender.com>)

Riffle 1.0.0 은 아래 「아직 닫히지 않은 검증」의 실사용 확인을 **건너뛰고** 냈다(사용자 결정 2026-09-27).

이 문서는 현재 구현과 검증 상태를 찾는 시작점이다. 날짜가 붙은 `docs/specs/`와
`docs/handoffs/`는 당시 결정과 증거를 보존하는 변경 이력이며, 후속 문서가 승계할 수 있다.
현재 사용자 동작은 README와 코드·테스트가 기준이고, 남은 작업은 `docs/backlog.md`가 기준이다.

## 현재 구현

- Windows 데스크톱과 Docker 웹(원격 웹)이 같은 Python 엔진과 같은 화면(`web/` → `riffle/ui/`)을 쓴다. 로컬 웹 판은 2026-09-26
  사용자 결정으로 걷었다 — 이 PC 는 데스크톱, 다른 기기는 원격 웹 두 갈래다.
  Android 앱은 2026-09-24 사용자 결정으로 걷었고, Sleek 인계 화면(합치기·원본 비교)도 같은 날 걷었다(명세
  `2026-09-24-01`). Sleek 이 사람 없이 Riffle 엔진을 부르는 경로는 남아 있고 `tests/test_sleek_engine_contract.py`가 지킨다.
- 화면은 명세 `2026-09-24-01`과 `docs/UX-철학.md`로 처음부터 다시 만들었다. 첫 화면은 놓는 곳 하나이고,
  놓은 파일로 할 일이 정해진다(필기 파일 + 새 PDF → 필기 옮기기, PDF 여러 개 → 문서 합치기).
- 문서 합치기: 놓은 순서대로 모든 쪽이 기본. 쪽 그림 누르기와 범위 칸이 같은 상태를 가리키고, 결과 줄에서 끌기나
  `‹ ›`로 순서를 바꾼다. 쪽 그림은 보일 때만 불러온다.
- 필기 옮기기: 서버 `riffle/review.py`가 기계가 자신 없는 쪽만 골라 이유 종류를 붙이고(칸 위 손필기 · 새 PDF 에 없는
  쪽 · 달라진 쪽 · 똑같은 쪽이 둘 · 자리가 많이 달라짐), 화면이 사람 말로 카드에 올린다. 카드마다 `맞아요`·`다른 쪽`·`빼기`.
  새 판에서 **순서가 바뀐 쪽**은 보통 짝만큼 닮았으면 카드 없이 다시 짝짓고(`riffle/reorder.py`, 엔진 뒤에 덧붙임), 애매하면
  옛 쪽과 후보 새 쪽을 나란히 놓은 "같은 쪽일까요?" 카드로 묻는다(명세 `2026-09-25-01`).
  `봐야 할 쪽` · `연결 보기` 두 보기(2026-09-25 `모든 쪽` 격자를 연결 보기로 바꿈 — 명세 `2026-09-25-03`). 연결 보기는 걸러 보기
  (순서 바뀜·새로 생긴 쪽·옛 쪽째 남김·여러 쪽 모음·칸 필기 옮김·볼 쪽·직접 고친 쪽·뺀 쪽)를 흐리게 보여 준다. 쪽을 누르면 크게
  보기(옛 쪽·새 쪽 나란히, 모인 쪽은 옛 쪽마다)에서 `다른 쪽`·`빼기`/`다시 넣기`로 고친다 — 자동으로 맞춘 쪽도 고칠 수 있다.
- 필기 옮기기를 저장하면 데스크톱에서만 이 PC 에 다시 돌려 볼 사례를 남긴다(`riffle/cases.py`, `%LOCALAPPDATA%\Riffle\cases`,
  지문과 짝만 — 파일 이름·그림 없음). 배포된 웹은 남기지 않는다.
  새로 생긴 쪽은 목록에 올리지 않는다(원칙 0). 확인하지 않은 카드가 남으면 저장 전에 한 번 묻는다.
- Samsung Notes, Notewise, Goodnotes 6 필기 이전은 쪽 추가·삭제, 쪽 제외와 PDF 비율·여백 변환을 지원한다.
- Sleek 필기본(오른쪽 필기 칸이 있는 PDF)은 칸을 빼고 짝을 짓는다(`riffle/sleek_notes.py`). 필기본 쪽이 아래로
  늘어난 경우도 원래 쪽 비율 부분만 비교한다.
- **새 파일이 Sleek 필기본이면 반복 묶음 단위로 짝짓는다**(명세 `2026-09-25-03`, `riffle/sleek_match.py`). 필기본 → 필기본은
  새 판이 정답: 결과 쪽 구조가 새 필기본 그대로이고, 반복 수가 바뀌면 옛 반복 쪽의 손필기를 상대 위치로 새 쪽에 나눠 얹으며(여럿이
  한 새 쪽에 모일 수 있다 — 쪽 계획의 `merged`), 새 판에 없는 빈 옛 쪽은 뺀다. 필기 칸의 손필기는 새 쪽의 여백으로 옮긴다
  (`riffle/page_ink.py`). 사람을 부르는 것은 손필기가 있는 옛 쪽이 새 판에 없을 때와 칸 여백이 모자랄 때뿐이다. 비 Sleek → 필기본은
  반복 묶음을 한 쪽처럼 짝짓고 합집합은 그대로다.
- 세 필기 형식은 분석·미리보기·저장을 한 길(`transfer_plan.inspect_pdfs`·`compose_slot_ink`·`preview_slot`)로 하고, 형식마다
  다른 것은 쪽 필기 바이트의 세 동작(객체 상자·객체마다 변환·합치기, `riffle/ink_layer.py`)뿐이다. Goodnotes 5 는 실물 샘플이 없어
  미확인 — 쪽 목록이 없는 파일은 옮기지 않고 알린다.
- 기본 화면은 결론 한 줄·알아 둘 것·카드(기계가 자신 없는 쪽)만. `연결 보기` 는 옛 파일·새 파일의 모든 쪽을 두 띠로 놓고 짝을 선으로
  잇는다(`web/src/links.ts`). 데스크톱 창은 제목 표시줄 없이 작업 영역을 채우고, 맨 위 막대가 끄는 자리·창 단추를 갖는다.
  아이콘은 Sleek 과 같은 틀.
- Samsung Notes 결과는 끝 표식(end_tag)의 노트 높이를 결과에 맞추고, 원본에만 있던 쪽을 맨 뒤에 둔다 — 2026-09-24
  「마지막 쪽이 안 보인다」의 원인이었다. 만든·고친 시각은 옮긴 시각으로 바꾼다.
- 새 PDF에 없는 기존 PDF 필기 쪽은 옛 배경·필기째 남긴다. SDOCX의 별도 노트 쪽도 가장 가까운 보존 원본 쪽 다음에
  배치하고 페이지 바이트를 그대로 보존한다. 새 PDF에 없는 옛 쪽은 필기가 없어도 제자리에 남긴다(합집합 — 2026-09-25
  사용자 결정, 명세 `2026-09-25-01`. 전에는 필기 없는 SDOCX 쪽을 자동 생략했다. Notewise·Goodnotes 는 원래 남겼다).
- Goodnotes 목차 입력·생성은 2026-09-07 사용자 결정으로 제거했다. 기존 목차를 잃을 수 있는
  원본의 저장 중단 검사는 유지한다.
- 정렬 가로·세로 배율 불일치, 최대 잔차 50mm 초과, 경계 이탈 추정 5mm 이상은 모든 짝지은 쪽을 확인할 쪽으로 올린다.
- 배경 배치와 비교 미리보기는 PDF의 CropBox·원점 이동·직각 회전을 유지한다. 데스크톱 배치를 원본
  렌더링 픽셀에 대조하는 회귀 테스트를 포함한다.
- 데스크톱·웹은 PyMuPDF를 유지한다. 개인 사용과 배포의 라이선스 조건은 README에 구분한다.
- 버전은 깃 태그 `vMAJOR.MINOR.PATCH`(모든 제품 공통 원칙)에서 파생한다. NotEditor 시절 태그는 `noteditor-v1.0.0`~`-v1.2.0` 으로
  옮겨 버전 계산(`git describe --match "v[0-9]*"`)에서 뺐다. 개발 체크아웃은 남은 빌드 파일보다 `git describe` 를 먼저 본다.
- 웹(Render 서비스 `riffle`)은 `release` 가지를 따라 배포되고, 그 가지는 릴리스 태그 때만 `release.yml` 이 옮긴다 — `main` 의
  개발 중 커밋은 배포되지 않는다. 옛 서비스 `noteditor`(<https://not-editor.onrender.com>)는 `noteditor-1.2` 가지에 고정.

## 자동 검증

- Python 단위·HTTP 테스트 252개, 화면 node 시험 35개(2026-09-27). CI(`test.yml`)가 둘 다와 Docker 빌드를 돌린다
- 화면: 빌드가 소스와 같은지(해시 대조), 화면 문구에 내부 용어가 없는지, 라이트·다크 글자 대비 4.5:1,
  화면 안 순수 함수 node 시험(파일 규칙·확인할 쪽 문장·짝 바꾸기·합치기 순서)
- Edge 1440×1000·390×844·다크 모드에서 첫 화면 거절 → 기다림 → 필기 옮기기 → 합치기 흐름, 가로 넘침·화면 오류 0
- 사람이 돌리는 측정: `tools/check_review_screen.py`(검토 화면 실제 파일 브라우저 확인, `--notes` 는 필기본 → 필기본), `tools/check_reorder.py`(새 PDF 쪽
  순서를 일부러 섞어 짝을 되찾는지, `--cases` 로 저장된 사례 다시 채점 — 조용히 틀린 짝이 하나라도 있으면 실패)
- 실제 파일 7쌍(족첵 2 · 옛 필기본 5)에서 확인할 쪽 목록 길이가 미리 적은 표와 같음, `다른 쪽`으로 바로잡은 저장 결과의
  필기 위치, 합치기 저장본의 쪽 순서가 화면 결과 줄과 같음

## 아직 닫히지 않은 검증

- 실제 강의로 새 화면 쓰기(백로그 「새 화면」 단위 7, 「검토 깊이」 단위 5)
- 데스크톱 창에 실제로 파일을 끌어다 놓기(마우스 조작이라 자동으로 못 했다 — 연결까지만 확인)
- 실제 태블릿에서 새 화면으로 만든 SDOCX·Notewise·Goodnotes 결과 가져오기(끝 쪽까지)와 펜·지우개 편집 왕복 —
  합친 쪽, 옮긴 칸 손필기, 쪽 안으로 밀어 넣은 획, 본떠 만든 빈 쪽 포함(「Sleek 필기본 갱신」 단위 8)
- Goodnotes 5 실물 샘플(「Sleek 필기본 갱신」 단위 7)
- Goodnotes 다중 페이지·가져온 PDF·스키마 24 실제 샘플
- Flexcil `.flex`와 편집 가능한 PDF 주석 실제 샘플

## 알려진 빈틈

- 서버가 보내는 오류 문구(예: 「정렬 배율을 정할 수 없습니다」)는 화면 문구 자동 검사 밖이다.

완료되지 않은 실기 검증은 자동 테스트 통과로 대신 닫지 않는다. 입력 원본은 항상 읽기 전용으로
다루고 결과는 새 파일로 저장한다.
