# 새 화면 — 원점에서 다시 짓는 NotEditor

**날짜:** 2026-09-24
**상태:** 명세 — 사용자 결정 넷 반영, 착수 전(아래 「열린 질문」 확인 후 작업 단위 1부터)
**판단 기준:** [`docs/UX-철학.md`](../UX-철학.md) — 판단이 갈리면 그쪽이 이긴다
**본뜬 절차:** Sleek 명세 `2026-09-16-02`(UX 철학 격상) → `2026-09-16-04`(새 화면)

> 이 문서의 본문은 **사용자가 보는 말**로만 쓴다. 코드 안의 이름은 맨 끝 「부록 — 만드는 사람을 위한
> 대응」에만 둔다. 본문에 코드 이름이 새어 나오면 그것은 이 문서의 버그다.

---

## 왜 하는가

1. **첫 화면이 무엇부터 할지 말해 주지 않는다.** 도구 탭 둘과 단추 여러 개(`문서 비우기`·`PDF 추가`·`PDF로 저장`
   …)로 시작한다. 사용자가 하려는 일은 거의 늘 "옛 필기를 새 PDF로 옮기기" 하나인데, 그 일이 두 번째 탭에 있다.
2. **엔지니어의 말로 말한다.** 분석 결과가 `공통 93쪽을 찾아 새 PDF 기준으로 재조립합니다`, `본문 배율 0.971배 ·
   이동 0.05, 7.76mm`, `Samsung 펜 캐시 12개`, `불확실 4쌍` 으로 나온다. 사용자가 해석해야 할 숫자다(원칙 1).
3. **확인할 것이 묻힌다.** 쪽 대응을 모든 쪽 한 줄씩 늘어놓는다. 95쪽이면 95줄이고, 봐야 할 두 쪽은 그 사이
   어딘가에 있다(원칙 0).
4. **아무도 부르지 않는 화면이 절반이다.** Sleek 인계 전용 모드(탭 잠금·다른 저장 단추·원본 비교 화면·진도 범위
   제안)가 화면 곳곳에 갈래를 만든다. Sleek 의 새 화면은 이것을 더 이상 부르지 않는다.
5. **한 화면이 네 실행 환경을 한꺼번에 품는다.** 데스크톱 창·로컬 웹·배포 웹·Android 의 차이가 한 파일(약
   2,000줄) 안에 갈래로 섞여 있어, 한 곳을 고치면 다른 곳이 깨질까 봐 모두 다시 봐야 한다.

고쳐 쓰지 않고 새로 짓는 이유: 1·3·4 가 "화면이 프로그램의 구조(도구별 탭·쪽 대응 표·인계 모드)를 따라 짜여
있다"는 한 뿌리에서 나온다. 고쳐 쓰면 그 뼈대를 물려받는다.

## 목표

**앱을 열면 "파일을 놓으세요" 하나만 보인다. 옛 필기와 새 PDF를 놓으면 끝까지 알아서 맞추고, 사람에게는
기계가 자신 없는 쪽만 보여 준 뒤, 새 파일로 저장한다.** 확인할 쪽이 없으면 놓고 → 저장, 두 번으로 끝난다.
Mac 의 미리보기(Preview) 앱처럼 조용하고 단정하게.

## 사용자가 실제로 하는 일

화면은 이 일들에서 끌어낸다. 빈도 높은 순.

| # | 하는 일 | 얼마나 자주 |
|---|---|---|
| 1 | 족첵 새 판이 나오면 옛 필기를 새 판으로 옮긴다 | 강의마다, 판이 바뀔 때 |
| 2 | 옛 필기를 Sleek 필기본(오른쪽에 필기 칸이 붙은 PDF)으로 옮긴다 | 필기본이 새로 나올 때 |
| 3 | 기계가 자신 없는 쪽을 보고 "맞다 / 다른 쪽이다 / 빼자"를 정한다 | 옮길 때 가끔 |
| 4 | 여러 PDF에서 쪽을 골라 하나로 합친다 | 가끔 |
| 5 | 결과 파일을 태블릿으로 가져간다 | 옮길 때마다 — 앱 밖의 일 |

**1·2 는 누르는 횟수를 가장 적게.** 3 은 확인할 것이 있을 때만 나타난다. 4 는 1 의 자리를 차지하지 않는다.
5 는 앱이 대신할 수 없지만(태블릿 파일을 가져오는 자동 경로가 없다) 저장한 파일을 바로 찾게 돕는다.

## 화면 구성

### 첫 화면 — 놓는 곳 하나

```
┌──────────────────────────────────────────────────┐
│ NotEditor                                         │
│                                                   │
│        ┌──────────────────────────────────┐       │
│        │                                  │       │
│        │     파일을 여기에 놓으세요           │       │
│        │                                  │       │
│        │  필기 파일과 새 PDF → 필기 옮기기    │       │
│        │  PDF 여러 개      → 문서 합치기     │       │
│        │                                  │       │
│        │          [ 파일 고르기 ]            │       │
│        └──────────────────────────────────┘       │
│                                                   │
└──────────────────────────────────────────────────┘
```

- 놓은 파일의 **종류와 개수로 할 일을 정한다.** 묻지 않는다.

  | 놓은 것 | 하는 일 |
  |---|---|
  | 필기 파일(Samsung Notes·Notewise·Goodnotes) 하나 + PDF 하나 | 필기 옮기기 |
  | PDF 둘 이상 | 문서 합치기 |
  | 필기 파일 하나만 | "새 PDF를 놓으세요" — 놓는 곳이 반쯤 찬 모양으로 기다린다 |
  | PDF 하나만 | "필기 파일을 함께 놓으면 필기를 옮기고, PDF를 더 놓으면 합칩니다" — 기다린다 |
  | 그 밖(필기 파일 둘, 모르는 형식) | 무엇이 안 되는지와 무엇을 놓으면 되는지를 한 줄로 |

- 파일을 하나씩 따로 놓아도 된다. 두 번째 파일이 오면 그때 정한다.
- 웹에서는 놓은 파일이 **올라가는 동안** 놓는 곳 안에 진행 막대가 보인다.

### 필기 옮기기 — 확인할 쪽만

파일이 갖춰지면 곧바로 맞추기를 시작하고, 끝나면 이렇게 보인다.

```
┌──────────────────────────────────────────────────┐
│ ←  병리학 1주차(3) 필기 → 1주차(3) 필기본          │
│                                                   │
│ 93쪽은 자동으로 맞췄습니다. 2쪽만 봐 주세요.        │
│                                                   │
│ ┌──────────┐ ┌──────────┐  새 판에서 새로 생긴 쪽    │
│ │  옛 24쪽   │ │  새 25쪽   │  같아 보이지만 형광펜이   │
│ │ (필기 겹침)│ │ (필기 겹침)│  달라 확신이 없습니다     │
│ └──────────┘ └──────────┘  [맞아요] [다른 쪽] [빼기] │
│ ──────────────────────────────────────────────── │
│ ┌──────────┐ ┌──────────┐  필기 칸 위의 손필기      │
│ │  옛 28쪽   │ │  새 28쪽   │  칸의 글이 바뀌었을 수    │
│ └──────────┘ └──────────┘  있습니다   [맞아요] [빼기] │
│                                                   │
│ 모든 쪽 보기 (95)                   [ 새 파일로 저장 ] │
└──────────────────────────────────────────────────┘
```

- **머리 한 줄이 결론이다.** 몇 쪽을 알아서 했고 몇 쪽을 봐야 하는지. 확인할 쪽이 0이면
  "95쪽을 모두 자동으로 맞췄습니다" 와 `새 파일로 저장` 만 있다.
- **확인할 쪽마다 이유를 사람 말로 한 줄.** 이유는 기계가 이미 아는 것에서만 나온다.

  | 기계가 아는 사실 | 화면의 말 |
  |---|---|
  | 똑같이 생긴 쪽이 떨어진 곳에 또 있다 | 새 PDF에 똑같은 쪽이 하나 더 있어 어느 쪽인지 확신이 없습니다 |
  | 생김새가 꽤 다르다 | 비슷하지만 달라진 곳이 있어 확신이 없습니다 |
  | 새 PDF에 없는 옛 쪽인데 필기가 있다 | 새 PDF에 없는 쪽입니다. 필기를 잃지 않게 옛 쪽째 남깁니다 |
  | 옛 판에 없던 새 쪽 | 새 판에서 새로 생긴 쪽입니다 (필기 없이 들어갑니다) |
  | 위치 맞춤이 불안하다 | 쪽 안 내용의 자리가 많이 달라져 필기 위치를 확인해 주세요 |
  | 필기 칸 위에 손필기가 있다 | 손필기가 필기 칸 위에 있습니다. 칸의 글이 바뀌었을 수 있습니다 |

- **쪽 그림 위에 실제 손필기를 겹쳐** 보여 준다. 판단은 그림으로 한다(원칙 2).
- 단추는 셋: `맞아요`(확인) · `다른 쪽`(새 PDF의 쪽을 골라 바꾸기) · `빼기`(결과에서 빼기, `다시 넣기` 로 되돌림).
  `다른 쪽` 을 누르면 새 PDF의 쪽들이 가로로 펼쳐지고 하나를 고른다. 바꾸면 영향을 받는 쪽이 목록에 새로 올라온다.
- **모든 쪽 보기** 는 접혀 있다. 펼치면 지금의 전체 대응 목록(끌어서 순서 바꾸기 포함)이 나온다 — 궁금할 때만 보는 깊이.
- **저장.** 확인하지 않은 쪽이 남아 있으면 저장 단추 옆에 "2쪽을 아직 보지 않았습니다"가 보이고, 누르면 한 번
  묻는다(`그대로 저장` · `돌아가기`). 지금의 명시 승인 규칙 그대로다(원칙 3).
- 맞추는 동안에는 진행 단계를 사람 말로: `쪽 짝짓는 중` → `필기 위치 맞추는 중` → `미리보기 만드는 중`.

### 문서 합치기

```
┌──────────────────────────────────────────────────┐
│ ←  문서 합치기 · 3개 문서                          │
│                                                   │
│ 약리학 3주차(1).pdf   쪽: [ 1-12, 15    ]           │
│  ▢▢▣▣▣▣ …                                         │
│ 약리학 3주차(2).pdf   쪽: [ 전체        ]           │
│  ▣▣▣▣▣ …                                          │
│ ──────────────────────────────────────────────── │
│ 결과 22쪽  ▣▣▣▣▣▣▣▣▣ … (끌어서 순서 바꾸기)          │
│                                    [ PDF로 저장 ]  │
└──────────────────────────────────────────────────┘
```

- 문서마다 쪽 그림 줄과 **쪽 범위 칸**(`1-3, 5, 8-`)이 있다. 그림을 눌러도, 범위를 써도 같은 선택이 된다.
- 기본은 **모든 쪽, 놓은 순서.** 고르지 않으면 그대로 이어 붙인다(원칙 4).
- 결과 줄에서 쪽을 끌어 순서를 바꾼다. `순서 되돌리기` 는 결과 줄이 기본 순서와 다를 때만 보인다.
- 문서를 더 놓으면 목록 끝에 붙는다.

### 저장한 뒤

- 데스크톱: 저장 위치를 고르는 창이 뜬다. 이름은 알아서 채운다(`<옛 이름>-필기.sdocx` 처럼). 저장하면
  "저장했습니다" 와 `폴더 열기` 가 잠깐 보인다.
- 웹: 곧바로 내려받는다.
- 한 줄 요약을 남긴다: `자동 93 · 확인 2 · 옛 쪽째 남김 0 · 뺀 쪽 0`. 무엇을 했는지 되짚을 수 있게(원칙 5).
- `←` 는 첫 화면으로 돌아간다. 고른 파일은 비워진다(웹에서는 올린 파일도 지운다).

### 오류

- **문구가 곧 할 일이다.** `암호화된 PDF는 옮길 수 없습니다. 암호를 푼 PDF를 놓아 주세요.`
- 빨간색은 실패에만 쓴다. "확인할 쪽"은 실패가 아니다 — 노란색 표시도 쓰지 않고 목록으로만 보인다.

### 없애는 것

- 도구 탭(`문서 합치기 | 필기 옮기기`) — 놓은 파일이 정한다.
- Sleek 인계 전용 모드 전부 — 잠긴 탭, `저장하고 Sleek으로 돌아가기`, 원본 비교 화면(`변화 없음`·`문제 수정됨`…),
  진도 범위 제안 단추, 인계로 열 때의 명령줄 옵션.
- 분석 결과의 수치 문구(배율·이동 mm·펜 캐시 개수·불확실 쌍) — 사람이 할 일을 바꾸지 않는 숫자다.
- Android 앱과 그 빌드.

## 모양 — 애플다움을 무엇으로 만드나

Sleek 명세 `2026-09-16-04` 「모양」과 같다. 두 앱이 한 벌처럼 보여야 한다.

- **글꼴:** Pretendard 를 앱에 넣는다. 크기는 몇 단계로만 — 큰 제목 · 제목 · 본문 · 보조. 굵기로 위계를 만든다.
- **색:** 바탕은 흰색/아주 옅은 회색, 글자는 검정과 두 단계 회색, **강조색 하나**(누를 수 있는 것에만).
  빨강은 실패에만. 다크 모드를 처음부터 함께 만든다(Windows 설정을 따른다).
- **여백:** 8의 배수. 테두리 선보다 여백과 옅은 배경으로 영역을 가른다.
- **움직임:** 짧게(0.2초 안팎). Windows 의 "애니메이션 효과 끄기"를 따른다.
- **말투:** 존댓말 평서문, 짧게. 느낌표·이모지 없음. 단추는 동사.
- **키보드 단축키를 두지 않는다**(Sleek 과 같게). 남기는 것은 시트를 닫는 `Esc`, 글자를 치던 칸의 `Enter` 뿐.
- **이름을 하나로:** 옮기기 전 파일은 **옛 필기**, 옮길 곳은 **새 PDF**, 그 쪽들은 **옛 N쪽 / 새 N쪽**.
  `기존`·`구판`·`원본`·`대상` 은 화면에서 쓰지 않는다(원칙 8).

## 성공 기준

- [ ] **화면에 코드 이름과 해석할 숫자가 없다.** 화면 파일과 서버가 보내는 화면 문구에서 내부 식별자·영어 내부
      용어·`mm`·`배` 같은 맞춤 수치를 찾는 **자동 검사**가 테스트에 있고 통과한다.
- [ ] **도구를 고르는 단계가 없다.** 첫 화면에 탭이 없고, 놓은 파일로 할 일이 정해진다(위 표의 다섯 경우를
      테스트가 모두 확인한다).
- [ ] **확인할 쪽이 없으면 놓기 → 저장, 누르는 곳이 두 번이다**(데스크톱은 저장 위치 창 제외).
- [ ] 확인할 쪽 목록에는 **기계가 자신 없는 쪽만** 있다. 실제 파일 7쌍(병리학 족첵 2 · 구필기본 5)으로 쪽마다
      "왜 목록에 있는지"를 단위 4 시작 때 표로 적고, 목록이 그 표와 같다. 2026-09-24 엔진 측정으로 이미 아는 것:
      족첵 2주차(1)은 생김새가 다른 4쪽, 구필기본 1주차4는 칸 위 손필기 1쪽, 1주차2·1주차A는 0쪽.
- [ ] 확인할 쪽마다 **이유가 한 줄**이고, 그 말은 위 표의 여섯 가지 중 하나다.
- [ ] 확인하지 않은 쪽을 남긴 채 저장하려면 한 번 묻는다(지금 규칙 유지 — 테스트).
- [ ] 저장한 Samsung Notes 결과를 **태블릿에서 열어** 끝 쪽까지 보이고 필기가 제자리다(사용자 확인).
- [ ] 문서 합치기: 범위 칸과 쪽 그림 선택이 같은 상태를 가리킨다. 기본(아무것도 안 고름)은 모든 쪽을 놓은 순서로.
- [ ] Sleek 인계 코드·명령줄 옵션·원본 비교 화면이 **지워졌다.** 그것만 검사하던 테스트도 함께 지운다.
- [ ] Android 폴더·빌드·자동 검증이 **지워졌다.** README 에 그 사실과 이유를 한 줄 남긴다.
- [ ] 옛 화면 파일이 **지워졌다.** 데스크톱 창과 웹이 같은 새 화면을 연다.
- [ ] 라이트·다크 모두에서 글자 대비가 4.5:1 이상이다(자동 검사).
- [ ] 1440×1000 과 390×844(좁은 창) 두 크기에서 첫 화면·필기 옮기기·합치기가 깨지지 않는다(브라우저 자동 확인).
- [ ] `docs/UX-철학.md` 체크리스트를 화면마다 훑은 결과가 이 명세의 변경 이력에 남고, "아니오"에는 이유가 붙는다.
- [ ] 사용자가 실제 강의로 **1·2번 일**을 해 보고 "됐다"고 한다.

## 범위 밖

- **맞추는 엔진의 판단 바꾸기.** 쪽 짝짓기·위치 맞춤·확인 필요 규칙은 지금 그대로 쓴다. 화면이 그 결과를 사람
  말로 옮길 뿐이다. 새 화면에 필요한 **읽기 API**(확인할 쪽과 그 이유 목록)만 더한다.
- **형광펜이 새로 칠해진 쪽을 짝짓는 개선** — 백로그에 따로 있다.
- **Sleek 저장소 쪽 인계 정리**(NotEditor 부르는 코드·API·"NotEditor 없음" 실패 종류) — Sleek 에서 따로 한다.
  이 명세는 NotEditor 쪽만 걷는다.
- 로그인·계정. 배포 웹의 접근 제어는 지금처럼 호스팅 쪽에 맡긴다.

## 제약

- 원본 파일은 읽기만 한다. 결과는 새 파일이다(원칙 3·7 — 바꾸지 않는다).
- 데스크톱 창은 지금처럼 pywebview 로 띄운다. 화면은 데스크톱·로컬 웹·배포 웹이 **같은 빌드 결과**를 쓴다.
  실행 환경의 차이(파일 고르기·저장·내려받기)는 화면 안의 한 곳(서버와 말하는 층)에서만 갈린다.
- 빌드 결과를 저장소에 커밋한다(Sleek 과 같게). 사용자 PC에 Node 가 없어도 앱이 뜬다.
- 새 화면으로 바꾸는 동안에도 필기 옮기기가 끊기지 않는다 — 옛 화면은 새 화면이 성공 기준을 채운 뒤에 지운다.

## 고려했다가 안 한 것

| 안 한 것 | 이유 |
|---|---|
| 사이드바형(Sleek 과 같은 틀) | NotEditor 는 목록을 오래 두고 보는 앱이 아니라 한 번에 한 일을 끝내는 앱이다. 사이드바는 고를 것을 늘린다(사용자 결정) |
| 위쪽 탭 두 개 유지 | 도구를 고르는 단계가 남는다. 파일 종류로 알 수 있는 것을 묻는 것이다(원칙 4, 사용자 결정) |
| 최근 작업 목록 | 결과는 사용자가 고른 자리에 저장되고 `폴더 열기` 로 바로 찾는다. 목록은 이 기기에만 남는 두 번째 기록이 된다 |
| 저장 위치를 묻지 않고 옛 필기 옆에 자동 저장 | 옛 필기는 보통 내려받기 폴더에 있어 결과가 섞인다. 지금처럼 이름만 채워 주고 위치는 사람이 고른다 |
| Sleek 인계를 새 모양으로 옮기기 | 부르는 곳이 없다(Sleek 새 화면이 인계 화면을 부르지 않음을 2026-09-24 확인). 사용자 결정 |
| Android 도 새 화면으로 | 실기 검증이 한 번도 닫히지 않았고, 사용자 결정으로 걷는다 |

## 열린 질문

1. **진도 범위 제안 엔진**(족첵에서 이번 강의 몫을 그림으로 찾아 주는 것)은 인계 없이도 합치기에 쓸모가 있다.
   다만 "후보 강의록"을 인계가 넘겨주던 것이라, 일반 합치기에서는 사용자가 강의록을 함께 놓아야 한다. 엔진은
   남기고 화면에서만 뺄지, 엔진째 지울지 — **기본안: 엔진째 지운다**(부르는 곳이 없으면 코드는 낡는다).
2. **로컬 웹 바로가기**를 남길지. 데스크톱 창과 같은 화면을 브라우저로 여는 두 번째 입구다 — **기본안: 남긴다**
   (사용자가 고른 "웹(로컬·배포)"에 들어 있다).
