## 왜 하는가 — 사용자 요청 (2026-09-25)

0. UX 철학과 Apple 디자인 가이드라인이 최우선이다.
1. 앱이 **전체 화면으로** 열리고, **제목 표시줄이 없고**, 레이아웃이 그에 맞게 자연스러워야 한다.
2. 기본은 사람이 쪽 짝을 검토하지 않고 **중요한 것만 알린다.** 자세히 보기에서는 쪽 짝이 **직관적으로 바로 눈에
   들어오게** 다시 짠다.
3. 앱 아이콘을 **Sleek 스타일로** 바꾼다.
4. **Sleek 필기본 → Sleek 필기본**(자동으로 알아본다)으로 필기를 넘길 때는 쪽의 변동을 읽어 알아서 동작한다.
   - 동일성은 **Sleek 필기 칸을 뺀 강의록 영역**으로 판정한다.
   - 필기본이 개정되어 같은 강의록 쪽의 **반복 수**가 바뀌어도 옛·새를 합치지 않는다(지금은 합집합이라 옛 필기본
     내용이 섞인다). **새 파일 내용만** 남긴다.
   - 옛 1쪽이 3번 반복되고 새 판은 2번이면, 옛 세 쪽의 손필기를 새 두 쪽 중 **상대 위치가 더 가까운 쪽**에 넣는다.
   - 새 판이 정답이므로 **확인 필요를 무책임하게 띄우지 않는다.** 순서 보존 규칙으로 최대한 짝짓는다.
   - 사용자 경험: 강의록 영역의 손필기는 같은 쪽의 강의록 영역에, Sleek 필기 칸의 손필기는 같은 쪽 필기 칸의
     **여백에**, 결과의 쪽 구조는 새 판과 **완벽하게 같게** — **처음부터 새 필기본에 손필기한 것처럼.**
5. 비 Sleek 파일 → Sleek 필기본에도 4의 것 중 맞는 것을 적용한다.
6. 모든 기능은 **Samsung Notes 를 정본**으로 두고 Notewise·Goodnotes 6·**Goodnotes 5** 도 완전히 같게 동작한다.
   유지보수를 위해 공통 층을 둔다.
7. 핵심 경험: 기본은 앱을 믿고 맡긴다. **불신이 생기면 원본 두 개와 그 사이의 짝을 한눈에** 확인할 수 있어야 한다.

## 목표

- 파일 두 개를 놓으면 끝까지 간다. Sleek 필기본끼리면 결과는 새 필기본과 쪽 수·쪽 순서가 같고, 손필기는 제 쪽
  제자리에 있다. 사람을 부르는 경우는 **손필기를 둘 곳이 정말 없을 때**뿐이다.
- 궁금하면 한 번 눌러 **연결 보기**로 들어간다 — 왼쪽 옛 파일, 오른쪽 새 파일, 그 사이를 잇는 선. 어느 옛 쪽의
  손필기가 어느 새 쪽으로 갔는지 스크롤 한 번으로 다 보인다.

## 판정 — Sleek 필기본끼리 (요청 4)

### 알아보기

Sleek 필기본 쪽은 두 흔적(왼쪽 위에 끼운 강의록 쪽 + 오른쪽 끝까지 쪽 높이를 채운 필기 칸)으로 알아본다(이미 있음).
더해서:

- **맨 앞 전용 쪽**(「강의를 시작하며」 — 강의록 쪽 없이 필기 칸만 있는 첫 쪽)도 필기본 쪽으로 본다.
- 쪽의 **절반 이상**이 필기본 쪽이면 그 파일을 필기본으로 본다. 설정·스위치는 없다(원칙 4).
- **반복 묶음:** 필기가 길면 Sleek 은 같은 강의록 쪽을 이어서 다시 싣는다. 이어진 쪽들이 **끼운 강의록 쪽의 내용이
  바이트까지 같으면** 한 묶음이다(실측: 그림으로 비교하면 흔들림 때문에 놓친다 — 병리학 1주차(1) 53쪽에서 반복
  12묶음을 정확히 잡음).

### 짝짓기

1. 옛·새 파일을 **묶음 단위**로 순서 보존 짝짓기한다. 비교는 강의록 영역 그림만 쓴다(이미 있는 쪽 지문).
2. 짝 못 지은 묶음이 두 짝 사이(같은 틈)에 옛·새 양쪽에 있으면 **그 틈 안에서 한 번 더** 순서대로 짝짓는다 —
   서로 다른 쪽의 실측 최소 거리(0.78) 아래면 짝이다. 요청 4 「순서 보존 규칙으로 최대한」.
3. 맨 앞 전용 쪽끼리는 그대로 짝이다.
4. **묶음 안 나누기(상대 위치):** 옛 묶음 n쪽 → 새 묶음 m쪽. 옛 k번째 쪽이 옛 묶음의 필기 흐름에서 차지하는 가운데
   자리(0~1)를 재고, 새 묶음에서 그 자리를 담은 쪽에 넣는다. 흐름은 쪽마다 필기 칸 글이 실제로 끝나는 높이로 잰다
   — 마지막 쪽이 반만 차 있어도 비율이 맞다. 예: 옛 3쪽 → 새 2쪽이면 옛 1쪽은 새 1쪽, 옛 2·3쪽은 대개 새 2쪽.
5. 새 판에 **없는** 옛 쪽:
   - 손필기가 없으면 **결과에 넣지 않는다**(새 판이 정답 — 요청 4). 연결 보기의 「뺀 쪽」에 보이고, 되돌릴 수 있다.
   - 손필기가 있으면(강의록 쪽 자체가 새 판에서 사라진 드문 경우) **옛 쪽째 남기고 카드로 알린다.** 원칙 7(한 획도
     버리지 않는다)이 쪽 구조 일치보다 위다. 이것이 사람을 부르는 첫째 경우다.

### 손필기 옮기기

- **강의록 영역의 획**은 그 쪽의 강의록 영역으로 옮긴다(강의록 쪽 상자 기준 변환 — 지금과 같다).
- **필기 칸과 늘어난 아래 칸의 획**(강의록 영역 밖)은 서로 가까운 획끼리 한 덩이로 묶어, 새 쪽의 **여백**으로 옮긴다.
  여백 = 새 쪽의 강의록 영역 밖에서 Sleek 글(과 이미 옮긴 다른 덩이)이 없는 곳. 원래 자리에 가장 가까운 빈자리를
  고르고, 모양·크기는 그대로다.
- 크기 그대로 들어갈 여백이 없으면 **줄여서**(90%부터 50%까지) 넣는다. 그래도 없으면 겹침이 가장 적은 자리에 두고
  **카드로 알린다.** 이것이 사람을 부르는 둘째 경우다.
- 여러 옛 쪽의 손필기가 한 새 쪽에 모이면 강의록 영역 획은 겹쳐 얹히고(같은 강의록 쪽이다), 칸 획 덩이는 서로
  겹치지 않게 차례로 자리를 잡는다.

### 사람을 부르지 않는 것

반복 묶음 사이의 애매함(똑같은 쪽이 이어짐), 칸 위 손필기(여백으로 옮기니 이제 확인할 일이 아니다), 새로 생긴
쪽·새 판에 없는 빈 옛 쪽(요약 숫자로만), 순서가 바뀐 묶음.

## 판정 — 비 Sleek → Sleek 필기본 (요청 5)

적용하는 것: 강의록 영역으로 동일성 판정(이미 있음) · 새 판의 **반복 묶음을 한 쪽처럼** 짝짓고 옛 쪽 손필기는
묶음의 **첫 쪽**에 얹는다(강의록 쪽이 처음 나오는 자리) · 틈 안에서 한 번 더 짝짓기 · 반복 때문에 카드 띄우지 않기.

적용하지 않는 것: **새 판에 없는 옛 쪽은 남긴다(합집합 유지).** 사용자가 2026-09-25 합집합을 정한 까닭이 바로 이
방향(족첵 → 필기본)에서 족첵 첫 장의 기출 색인이 빠질 뻔한 일이었다. 옛 파일이 필기본이 아니면 그 쪽은 "옛 필기본
내용"이 아니라 새 판에 없는 강의 자료다. 필기 칸이 없으니 칸 여백 옮기기도 해당 없다.

## 공통 층 — 네 형식 같게 (요청 6)

- 판정(짝짓기·반복 나누기·여백 자리)은 형식과 무관한 한 곳에서 한다. 형식마다 다른 것은 **세 가지 동작**뿐이다:
  쪽의 필기 객체마다 상자 읽기 · 객체마다 다른 변환 적용하기 · 여러 쪽의 객체를 한 쪽에 합치기.
- **미리보기와 저장이 같은 길을 쓴다.** 미리보기는 저장할 바이트를 실제로 만들어 그것을 그린다 — 화면에 보인
  자리와 파일 속 자리가 어긋날 수 없다(원칙 5).
- Samsung Notes 가 정본이다. 나머지 셋은 같은 계획을 받아 같은 결과를 낸다. 시험도 한 벌로 네 형식을 돈다.
- **Goodnotes 5:** 지금 `.goodnotes` 읽기는 Goodnotes 6 의 사건 기록(`index.events.pb`)에 기대고 있다. Goodnotes 5
  파일이 같은 구조인지 **실제 파일이 없어 확인하지 못했다.** 사용자 샘플을 받아 판정한다(단위 7). 구조가 같으면
  그대로 되고, 다르면 읽는 층만 더한다 — 공통 층 덕분에 판정·배치는 다시 짜지 않는다.

## 화면 (요청 1·2·3·7)

### 창 — 제목 표시줄 없는 전체 화면

- 데스크톱 앱은 **화면을 꽉 채운 창**(최대화)으로, **Windows 제목 표시줄 없이** 연다. 작업 표시줄은 가리지 않는다
  (파일을 끌어다 놓을 탐색기 창으로 오갈 수 있어야 한다).
- 맨 위 막대가 제목 표시줄 노릇을 한다: 빈 곳을 끌면 창이 움직이고, 두 번 누르면 최대화·복원. 오른쪽 끝에 창 단추
  셋(최소화·최대화/복원·닫기) — Windows 사용자가 찾는 자리다(Apple HIG: 플랫폼의 관례를 따른다).
- 웹은 브라우저가 창을 갖고 있으니 바꾸지 않는다.

### 기본 화면 — 알릴 것만

```
┌──────────────────────────────────────────────────────────────┐
│ ←  Riffle                                      ─  ▢  ✕      │  ← 끌면 창이 움직인다
│                                                              │
│  필기를 옮겼습니다                                            │
│  병리학 1주차(1) … 필기.sdocx → … 필기.pdf                     │
│  새 필기본 50쪽에 손필기 211획을 그대로 얹었습니다.             │
│  · 필기본이 바뀌어 옛 53쪽을 새 50쪽에 나눠 얹었습니다  [보기] │  ← 알림은 숫자와 보기 하나
│                                                              │
│  (볼 것이 있으면 카드 — 없으면 카드 자리가 없다)                │
│                                                              │
│  연결 보기 ›                                                  │  ← 불신이 생기면
│ ──────────────────────────────────────────────────────────── │
│                                         [새 파일로 저장]      │
└──────────────────────────────────────────────────────────────┘
```

- 카드는 지금처럼 기계가 자신 없는 것만. Sleek 필기본끼리면 대개 0장이다.
- 알림 줄은 사람이 알아 둘 일(반복 수가 바뀜, 새 판에 없는 빈 옛 쪽을 뺌, 순서 바뀜)을 한 줄씩, 끝에 `보기`.

### 연결 보기 — 원본 둘과 그 사이의 짝

```
 옛 파일 (53쪽)               새 파일 (50쪽)
 ┌──────┐                    ┌──────┐
 │ 옛 1 │────────────────────│ 새 1 │
 └──────┘                    └──────┘
 ┌──────┐                    ┌──────┐
 │ 옛 2 │──────────┐    ┌────│ 새 2 │
 └──────┘          │    │    └──────┘
 ┌──────┐          ├────┘
 │ 옛 3 │──────────┘            ← 여러 옛 쪽이 한 새 쪽으로 모인다(반복 수가 바뀜)
 └──────┘
 ┌──────┐
 │ 옛 4 │  ╳ 뺌                  ← 새 판에 없는 빈 옛 쪽
 └──────┘
```

- 왼쪽 세로 띠에 옛 파일의 모든 쪽(옛 손필기째), 오른쪽에 새 파일의 모든 쪽(옮긴 손필기째), 가운데에 짝을 잇는 선.
  선은 기본 회색, 사람이 볼 것은 주황, 사람이 고친 것은 파랑, 새 판에서 순서가 바뀐 것은 굵게. 짝이 없는 쪽은 선이
  없고 쪽 아래에 한 단어(`새로 생김` · `뺌` · `옛 쪽째 남김`).
- 두 띠는 **함께 흐른다** — 옛 쪽들과 그 짝인 새 쪽이 같은 높이에 온다. 여러 옛 쪽이 한 새 쪽으로 모이면 새 쪽 옆에
  빈자리가 생기고 선이 모인다. 한눈에 "어디가 어디로 갔는지" 보인다.
- 쪽이나 선을 누르면 **크게 보기**(지금의 크게 보기: 옛·새 나란히) — 거기서 `다른 쪽` · `빼기` · `다시 넣기`.
- 걸러 보기는 연결 보기 위에 그대로 둔다(볼 쪽·순서 바뀜·새로 생긴 쪽·뺀 쪽…).

### 아이콘 — Sleek 스타일

흰 둥근 사각형, 옅은 회색 테두리, 가운데 굵은 검은 선 그림 하나(Sleek 과 같은 굵기·여백). 그림은 **부채꼴로 펼쳐진
종이 몇 장**(riffle — 책장을 훌훌 넘긴다) — 쪽을 다루는 앱임을 말한다.

## 작업 단위

| 단위 | 내용 | 확인 |
|---|---|---|
| 1 | ✅ 필기본 알아보기 확장(맨 앞 쪽·파일 판정·반복 묶음) + 묶음 짝짓기·반복 나누기·틈 짝짓기 | 병리학 1주차 샘플 5개(옛 필기본 + 손필기 → 지금 필기본) |
| 2 | ✅ 공통 층: 형식별 세 동작 + 여백 자리 계획. 쪽 계획에 「이 새 쪽에 함께 얹는 옛 쪽」 | 합성 파일 시험(세 형식) |
| 3 | ✅ 세 형식의 저장·미리보기를 공통 층으로 | 기존 시험 전부 + 새 시험 |
| 4 | ✅ 화면: 기본 화면 알림 · 연결 보기 · 크게 보기에서 여러 옛 쪽 | node 시험 + Edge 두 크기 |
| 5 | ✅ 데스크톱 창: 제목 표시줄 없음·최대화(작업 영역)·창 단추 | 창을 띄워 확인 |
| 6 | ✅ 아이콘 | 아이콘 시험·눈으로 |
| 7 | Goodnotes 5 — **사용자 샘플 필요**(조사만 함, 변경 이력) | 샘플 받은 뒤 |
| 8 | 사용자: 태블릿에서 결과 열기(끝 쪽까지, 모인 쪽·여백으로 옮긴 획 편집), 데스크톱 창을 실제로 써 보기 | 사람 |

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 반복 쪽을 그림 지문이 같은지로 묶기 | 렌더 흔들림으로 놓친다(실측 1주차(1): 그림 해시로 0묶음, 내용 바이트로 12묶음) |
| 반복 나누기를 쪽 번호 비율로(n→m) | 마지막 쪽이 반만 찬 경우 어긋난다. 필기 칸 글이 끝나는 높이로 잰다 — 사용자가 말한 "상대 스케일" 그대로 |
| 칸 위 손필기를 Sleek 글 옆 문맥(가까운 글줄)에 붙이기 | 새 판에서 글이 바뀌면 붙일 곳이 없다. 원래 자리에서 가장 가까운 빈자리가 예측 가능하다 |
| 필기본 → 필기본에서도 합집합 유지 | 사용자 결정: 새 판이 정답. 옛 필기본 글이 결과에 섞인다(요청 4) |
| 비 Sleek → 필기본에서 합집합 걷기 | 합집합을 정한 사례가 바로 이 방향이다(기출 색인) |
| 진짜 전체 화면(작업 표시줄까지 가림) | 파일을 끌어올 탐색기로 못 간다. 최대화가 사용자가 말한 전체 화면에 가깝다 |
| 칸 여백이 모자라면 먼저 50%까지 줄이고 그다음 강의록 빈칸 | 크게 줄인 손글씨는 읽기 어렵다. 여백 80% → 강의록 빈칸 80% → 둘 다 50% 차례(사용자 결정 2026-09-25) |
| 강의록 빈칸을 글 줄(낱말 상자)로만 찾기 | 슬라이드의 그림·도형 위에 손필기를 얹게 된다. 쪽을 그려 바탕색과 다른 칸을 모두 피한다 |
| Goodnotes 5 알림에 "Goodnotes 6 에서 다시 내보내면 된다" 권하기 | 확인하지 않은 주장이다(원칙 5). 옮기지 않았다는 사실과 원본이 그대로라는 것만 말한다 |
| 아이콘 종이를 부채꼴로 기울이기 | 사용자 요청으로 평행하게 왼쪽 아래로 겹치게 바꿈(2026-09-25) |
