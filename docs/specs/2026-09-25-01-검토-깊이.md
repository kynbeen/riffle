# 검토 깊이 — 원하면 모든 쪽을 보고 고친다

**날짜:** 2026-09-25
**상태:** 진행 중
**판단 기준:** [`docs/UX-철학.md`](../UX-철학.md) — 판단이 갈리면 그쪽이 이긴다
**앞선 명세:** [`2026-09-24-01-새-화면`](2026-09-24-01-새-화면.md) — 그 명세의 화면 위에 짓는다

> 이 문서의 본문은 **사용자가 보는 말**로만 쓴다. 코드 안의 이름은 맨 끝 「부록 — 만드는 사람을 위한 대응」에만 둔다.

---

## 왜 하는가

2026-09-25 새 화면을 Apple Human Interface Guidelines(애플의 화면 설계 지침)와 UX 철학으로 평가했다. 실제 파일
(병리학 1주차(3) 옛 필기 → Sleek 필기본, PDF 2개 합치기)로 브라우저에서 끝까지 돌려 본 결과다.

1. **깊이가 없다.** 기본 화면("93쪽은 자동으로 맞췄습니다. 2쪽만 봐 주세요")은 좋지만, 그 아래 단계가 사실상 없다.
   `모든 쪽 보기` 는 `옛 1쪽 → 새 1쪽 · 자동` 같은 글자 97줄이고 고칠 수 없다. 기계가 자신 있게 짝지었는데 틀린
   쪽은 고칠 길이 없다(앞선 명세가 적어 둔 빈틈). 새로 생긴 쪽·필기가 없어 뺀 쪽은 각주 한 줄로만 알리고 볼 수 없다.
2. **"새 PDF에 없는 쪽" 카드가 판단을 그림으로 못 하게 한다.** 옛 쪽 그림 한 장만 있고, 문구는 "새 PDF의 다른
   쪽과 같은 쪽이라면 **빼도 됩니다**" 다. 빼면 그 쪽의 손필기는 결과에 들어가지 않는다 — 원칙 7(작업 보존, 최우선)
   쪽으로 사람을 잘못 이끈다. 이번 파일의 옛 24·33쪽은 실제로 새 25·35쪽과 같은 쪽이었다(~~형광펜만 새로 칠해짐~~ → 바로잡음: 새 판에서 **순서가 바뀐** 쪽이었다, 변경 이력).
   그 두 새 쪽은 바로 위 각주 "새로 생긴 2쪽은 필기 없이 들어갑니다" 에 숨어 있었다. 사람이 `다른 쪽` 을 눌러
   97쪽 띠를 1쪽부터 훑어야 찾을 수 있고, 띠의 그림(132px)은 필기본 쪽을 알아볼 수 없을 만큼 작다.
3. **검토한 것을 잃거나, 결과를 사실과 다르게 말하는 경로가 있다.**
   - 저장한 뒤 카드에서 `빼기` 를 누르면 저장 완료 요약이 `뺀 쪽 0` → `뺀 쪽 1` 로 바뀐다. 파일은 그대로다. 저장
     단추도 돌아오지 않아 바꾼 것을 저장할 길이 없다(브라우저로 재현함). 원칙 5.
   - `←` 는 묻지 않고 비운다. 원본은 남지만 사람이 `다른 쪽` 으로 고른 짝 같은 **판단**은 사라진다.
   - 필기 옮기기 화면은 창에 놓인 파일을 받아 주지 않는다. 웹에서는 브라우저가 그 파일을 열어 버려 작업이 통째로
     사라질 수 있다(코드로 확인. 실제 끌어다 놓기는 마우스 조작이라 못 해 봄).
4. **저장 단추가 스크롤 맨 아래에 있다.** 카드 2장이면 1440×1000 창에서 이미 첫 화면 밖이다. 확인을 마친 카드는
   흐려지기만 하고 높이는 그대로라, 남은 카드가 위로 올라오지 않는다.

## 목표

**기본 화면은 지금처럼 "봐야 할 쪽만" 보인다. 원하면 한 번 눌러 결과 문서 전체를 쪽 그림으로 펼쳐 보고, 어느 쪽이든
크게 보고 고칠 수 있다.** 짝을 못 지은 옛 쪽 근처에 짝 없는 새 쪽이 있으면 둘을 한 카드에 나란히 놓아 "같은 쪽인가"를
그림으로 정하게 한다. 검토한 결과는 저장 전까지 잃지 않고, 저장한 뒤에는 저장한 그대로를 말한다.

이것은 Apple 이 점진적 공개(progressive disclosure — 기본은 단순하게, 원하면 한 단계 들어가 전부 보게)라고 부르는
방식이다. 원칙 0(자동이 기본)과 부딪히지 않는다 — 전체 검토는 **궁금한 사람만 들어가는 깊이**이지 거쳐야 하는 단계가 아니다.

## 화면 구성

### 머리 — 두 보기

```
┌────────────────────────────────────────────────────────────┐
│ ←  필기 옮기기                    [ 봐야 할 쪽 2 | 모든 쪽 97 ] │
│ 93쪽은 자동으로 맞췄습니다. 2쪽만 봐 주세요.                     │
│ …                                                          │
│ ───────────────────────────────────────────────────────── │
│                          2쪽을 아직 보지 않았습니다 [새 파일로 저장] │ ← 늘 보이는 아래 막대
└────────────────────────────────────────────────────────────┘
```

- 위쪽에 두 칸 전환 단추(세그먼트 컨트롤): `봐야 할 쪽 N` · `모든 쪽 N`. 봐야 할 쪽이 있으면 앞 칸에서 시작하고,
  0이면 뒤 칸에서 시작한다. 한 화면 안의 전환이라 단계가 늘지 않는다.
- **저장 막대는 아래에 붙어 늘 보인다.** 어느 보기에 있든, 스크롤을 어디까지 내렸든.
- 확인을 마친 카드는 **한 줄로 접힌다**(`옛 24쪽 → 새 25쪽 · 확인했습니다 · 되돌리기`). 남은 카드가 위로 올라온다.

### 짝 후보 카드

짝을 못 지은 옛 쪽(필기 있음) **근처**에 짝 없는 새 쪽이 있으면, 두 쪽을 한 카드에 나란히 놓는다.

```
┌──────────┐ ┌──────────┐  같은 쪽일까요?
│  옛 24쪽   │ │  새 25쪽   │  새 판에서 생김새가 달라져 짝을 확신하지
│ (필기 겹침)│ │ (필기 얹음)│  못했습니다. 같은 쪽이면 필기를 새 25쪽에
└──────────┘ └──────────┘  얹습니다.
                            [같은 쪽이에요] [아니에요] [다른 쪽]
```

- `같은 쪽이에요` → 옛 필기를 새 25쪽에 얹는다(지금의 `다른 쪽` 으로 고른 것과 같은 결과). 확인한 것으로 친다.
- `아니에요` → 지금의 "새 PDF에 없는 쪽" 카드로 돌아간다(옛 쪽째 남김).
- 후보가 없으면 지금처럼 "새 PDF에 없는 쪽" 카드이되, 문구에서 "빼도 됩니다" 를 걷는다. 같은 쪽이 있으면 `다른 쪽` 으로
  고르라고 말한다. 빼는 것은 사람이 스스로 고르는 일이지 앱이 권하는 일이 아니다(원칙 7).
- `다른 쪽` 의 띠는 **후보 근처에서** 시작한다(지금은 1쪽부터).
- **근처**의 정의 — 쪽 순서에서 가까운 짝 없는 새 쪽. 2026-09-25 실측: 1주차(3)에서 옛 24쪽의 짝(새 25쪽)은 옛 24 **바로
  다음 틈이 아니라 한 칸 뒤**에 있었다(`옛23→새23 · 옛24→(없음) · 옛25→새24 · (없음)→새25`). 옛 33쪽도 같은 모양(새 35쪽).
  그래서 "앞뒤로 짝지어진 두 쪽 사이의 틈"만 보는 규칙은 틀린다. 순서상 몇 칸 안에서 찾는다(칸 수는 열린 질문 1).

### 모든 쪽 — 결과 문서를 쪽 그림으로

```
 전체 97 · 새로 생긴 쪽 2 · 옛 쪽째 남김 2 · 필기 없어 뺀 쪽 0 · 직접 고친 쪽 0
 ▢ ▢ ▢ ▢ ▢ ▢ ▢ ▢      결과 순서대로, 필기를 얹은 쪽 그림
 ▢ ▢ ▣ ▢ ▢ ▢ ▢ ▢      ▣ = 표시가 붙은 쪽(「새 쪽 · 필기 없음」「옛 쪽째 남김」「직접 고름」…)
 ┄ 필기 없는 옛 1쪽 뺌 ┄   빠진 쪽은 원래 자리에 접힌 줄로. 누르면 펼친다
```

- **결과 순서대로** 필기를 얹은 쪽 그림 격자. 자동으로 맞춘 쪽에는 표시가 없다. 표시는 사람이 알아 둘 것에만.
- **요약 숫자가 곧 거르는 단추다.** `새로 생긴 쪽` 을 누르면 그 쪽들만 남는다. 각주 "새로 생긴 2쪽은 필기 없이
  들어갑니다" · "필기가 없는 옛 쪽 N쪽은 뺐습니다" 에도 `보기` 가 붙어 같은 걸러 보기로 간다.
- **빠진 쪽은 원래 자리에** 접힌 줄로 둔다. 따로 모으면 어디서 빠졌는지 모른다.
- 쪽 그림을 누르면 **크게 보기**: 옛 쪽과 새 쪽을 크게 나란히(짝이 있으면), 카드와 같은 단추(`다른 쪽` · `빼기` /
  `다시 넣기`), `이전` · `다음` 으로 넘긴다. Mac 의 Quick Look(스페이스바로 파일을 크게 보는 기능)과 같은 자리다.
- 자동으로 맞춘 쪽을 사람이 고치면 그 쪽에 `직접 고름` 표시가 붙고 숫자가 바뀐다. 사람이 고른 것이 이긴다(원칙 3·7).
- 그림은 **보일 때만** 불러온다. 97쪽을 한 번에 만들지 않는다.
- 전부 확인해야 저장되는 것이 **아니다**. 확인은 선택이다(원칙 0).

### 저장한 뒤

- 저장 완료 요약은 **저장한 순간의 숫자**로 고정한다.
- 저장한 뒤 무언가를 바꾸면 저장 막대가 다시 나타나고 `저장한 뒤 바꾼 것이 있습니다` 를 보인다.

### 잃지 않기

- `←` — 사람이 카드나 격자에서 하나라도 정했고 아직 저장하지 않았으면 한 번 묻는다(`처음으로` · `돌아가기`).
  정한 것이 없거나 저장했으면 묻지 않는다.
- 필기 옮기기 화면에 파일을 놓으면 받아서 버리지 않고, 브라우저가 파일을 열지도 않게 한다. 한 줄로 알린다:
  `지금은 필기를 옮기는 중입니다. 다른 파일로 시작하려면 ← 로 처음으로 가세요.`

## 범위 밖

- **쪽 짝짓기 엔진의 판단 바꾸기.** 엔진(`page_match`)은 그대로다 — Sleek 이 사람 없이 직접 부른다. 순서가 바뀐 쪽을
  다시 짝짓는 일은 필기 옮기기 분석에서 엔진 **뒤에** 덧붙인다(2026-09-25 사용자 결정, 변경 이력).
- **첫 화면에서 잘못 놓은 파일을 치울 수 없는 문제**(재현함 — 잘못 놓은 PDF가 붙잡혀 계속 따라온다). 검토와 다른
  화면이라 백로그 「새 화면」에 따로 둔다.
- 문서 합치기 화면의 작은 것들(범위 칸 오류 때 입력이 사라짐, 결과 줄의 "1번 문서" 번호가 위 목록에 없음, `‹ ›` 단추가
  작음, 문서 `빼기` 되돌리기 없음) — 백로그.
- 키보드 단축키. 앞선 명세의 결정(두지 않는다)을 그대로 따른다. 크게 보기의 넘기기는 화면 단추로 한다.

## 제약

- 원본 파일은 읽기만 한다. 결과는 새 파일이다(원칙 3·7).
- **Sleek 이 부르는 엔진 입구를 건드리지 않는다**(`tests/test_sleek_engine_contract.py`). 2026-09-24 이름을 바꿀 때 한 번
  끊겼다 — 화면만 보고 이 경로를 놓쳤다.
- 확인할 쪽을 고르는 규칙은 서버 한 곳, 사람이 읽을 말은 화면 한 곳에 둔다(앞선 명세와 같다 — 같은 말이 두 곳에 생기면
  한쪽이 낡는다).
- 빌드 결과를 커밋한다. 사용자 PC에 Node 가 없다. 소스를 고치고 빌드를 잊으면 해시 대조 테스트가 잡는다.
- ~~짝 후보는 자동으로 짝짓지 않는다~~ → 보통 짝만큼 자신 있으면(거리·차이 기준이 엔진의 보통 짝과 같다) **자동으로 짝짓고**,
  애매할 때만 사람이 본다(원칙 0, 사용자 결정 2026-09-25). 원래 제약은 "형광펜 때문에 생김새가 다르다"는 틀린 전제 위에 있었다.

## 고려했다가 안 한 것

| 안 한 것 | 이유 |
|---|---|
| 전체 확인을 저장 전 필수 단계로 | 95쪽을 다 보라는 것이 된다. 원칙 0 을 무너뜨린다 |
| 새로 생긴 쪽을 전부 카드로 올리기 | 필기가 없어 잃을 것이 없다. 카드가 늘면 정말 봐야 할 것이 묻힌다. 짝 후보가 될 때만 카드로 |

## 열린 질문

1. **짝 후보의 "근처"를 몇 칸으로 할지, 생김새 거리도 볼지.** 기본안: 순서상 ±3칸 안의 짝 없는 새 쪽 중 생김새가
   가장 가까운 하나. 7쌍 실측 표로 정한다(틀린 후보 0 이 먼저).
2. **1주차(3)의 `옛 25 → 새 24` 짝이 맞는지** — 순서가 국소적으로 뒤바뀐 것인지, 자신 있게 틀린 짝인지 **미확인**.
   틀린 짝이라면 "자신 있게 틀린 쪽"의 실제 예이고, 모든 쪽 보기가 필요한 근거가 하나 더 생긴다. 단위 2 에서 그림으로 확인한다.
3. **97쪽 격자의 그림 비용.** 필기를 얹은 쪽 그림을 쪽마다 서버가 만든다. 얼마나 걸리는지 미확인. 기본안: 보일 때만
   부르고, 느리면 격자 전용 작은 그림 입구를 더한다.
4. **필기 없는 옛 쪽도 짝 후보 카드로 올릴지.** 합집합으로 바꾸면서, 짝을 못 지은 필기 없는 옛 쪽이 근처의 짝 없는 새 쪽과
   같은 쪽이면 결과에 같은 슬라이드가 둘 들어간다. 잃을 필기는 없다. 기본안: 올리지 않는다(원칙 0 — 잃을 것이 없다). 단위 2 의 7쌍
   표에서 실제로 그런 쪽이 있는지 보고 정한다(2026-09-25 측정에서는 0쪽).
