**날짜:** 2026-09-25

**관련 명세:** `docs/specs/2026-09-24-01-새-화면.md` (판단 기준 `docs/UX-철학.md`)

## 현재 상태

새 화면 명세의 작업 단위 0~6이 끝났다. 데스크톱 창(`python -m riffle`)과 웹(`/`)이 같은 새 화면(`web/` 소스 →
`riffle/ui/` 빌드, 커밋함)을 열고, 옛 화면(`riffle/static/`)은 지웠다. 전체 시험 236개 통과, Edge 세 조건
(1440×1000·390×844·다크)에서 화면 오류 0. 남은 것은 **단위 7 — 사용자가 실제 강의로 써 보고 "됐다"고 하는 것**
(태블릿에서 결과 열기, 데스크톱 창에 파일 끌어다 놓기 포함). **로컬 `main` 은 원격보다 15커밋 앞서 있고 아직 푸시하지
않았다** — 아래 블로커 참고.

## 내린 결정과 근거

- **사용자 결정(2026-09-24):** 사람이 쓰되 자동이 기본 · Sleek 인계 화면 없앰 · Windows 데스크톱 + 웹(로컬·Render)만 ·
  첫 화면은 "파일을 놓으면 알아서". 기본값 React + Vite · Pretendard. 진도 범위 엔진은 엔진째 삭제, 로컬 웹 바로가기는 유지.
- **Render(웹 배포 서비스):** 옛 서비스 `noteditor` 는 v1.2.0 에 고정하고, Riffle 1.0 은 새 서비스로 연다(사용자 결정).
  고정용 가지 `noteditor-1.2` 는 이미 올렸다.
- **엔진의 정렬 경고 문장은 화면에 안 보인다.** 배율·mm 는 사람이 할 일을 바꾸지 않는다(원칙 1). 대신 그 경우 짝지은
  쪽 전부가 「쪽 안 내용의 자리가 많이 달라졌습니다」 카드로 오른다(`riffle/review.py` 의 `alignment`).
- **빌드 결과를 커밋한다.** 앱을 쓰는 PC 에 Node 가 없다. 소스를 고치고 빌드를 잊으면 `tests/test_new_ui.py` 가 해시로 잡는다.
- **`Merge.tsx` 옆 순수 함수 파일 이름은 `merging.ts`.** Windows 는 대소문자를 안 가려 `merge.ts` 와 부딪혔다.
- **사용자 쪽 미커밋 변경 세 파일은 건드리지 않았다**(아래 블로커).

## 미해결 질문 / 블로커

- **푸시 보류(가장 중요).** 옛 Render 서비스 `noteditor` 가 `main` 을 따라 자동 배포된다. 사용자가 Render 대시보드에서
  그 서비스의 배포 가지를 `noteditor-1.2` 로 바꾸기 전에 `main` 을 올리면 옛 주소에 Riffle 코드가 올라간다. 로그인이 필요해
  사용자만 할 수 있다. 바꿨다는 말을 들은 뒤 `git push origin main`(이 인계 커밋 포함 16커밋).
  → 그 전까지 **다른 기기에서는 이 인계 문서를 볼 수 없다**(이 PC 에만 있음).
- **작업 트리에 남은 사용자 쪽 변경:** `riffle/version.py`(개발 체크아웃에서는 남은 빌드 도장보다 `git describe` 를
  먼저 믿기), `tests/test_version.py`, `README.md` 두 줄. 이 세션이 만든 것이 아니라 커밋하지 않았다. 사용자에게 커밋할지 물을 것.
- 카드에 오르지 않은 쪽이 틀렸을 때 고칠 길이 없다(백로그 「새 화면」).
- 서버 오류 문구(「정렬 배율을 정할 수 없습니다」 등)는 화면 문구 자동 검사 밖이다(백로그).
- 옛 `-필기.sdocx` 수리 도구를 만들지 — 사용자 답 없음.

## 다음 단계

1. 사용자에게 Render `noteditor` 가지 전환 여부를 묻고, 됐으면 `git push origin main`.
2. 사용자 쪽 미커밋 세 파일을 커밋할지 묻는다(시험 `venv\Scripts\python.exe -m unittest discover -s tests` 로 먼저 확인).
3. 단위 7: 사용자가 실제 강의로 옮기기·합치기를 해 보고, 태블릿에서 결과를 끝 쪽까지 연다. 걸린 점을 명세 변경 이력에 적는다.
   특히 "카드에 없는 쪽이 틀렸던 적이 있었는지"를 물어 `모든 쪽 보기` 편집 여부를 정한다.
4. 단위 7 이 닫히면 백로그 「Riffle 1.0 배포」: `riffle/version.py` 의 `git describe --match 'riffle-v*'`, `release.yml`
   태그 조건을 `riffle-v*` 로, 태그 `riffle-v1.0.0`, 새 Render 서비스를 Blueprint(`render.yaml`)로(사용자).
5. Sleek 저장소: 쓰지 않는 인계 코드 걷기와 `noteditor_link` 같은 옛 이름 정리(Riffle 엔진 호출 경로는 살아 있으니 건드리지 말 것 —
   `tests/test_sleek_engine_contract.py` 가 지킨다).
