  390×844 다크)로 돌려 봄. 찾은 구멍: 저장 뒤 요약이 거짓·저장 단추 사라짐, 잘못 놓은 PDF 를 못 치움, "새 PDF 에 없는 쪽" 카드가

  단추가 스크롤 끝, 쪽 그림 확대 불가.
- **명세 두 개:** `2026-09-25-01-검토-깊이`(원하면 모든 쪽을 보고 고친다), `2026-09-25-02-버그-리포트와-사용-데이터`.

## 내린 결정과 근거

- **합집합(사용자 결정):** 옛 판에만 있던 내용도 사람이 들인 것의 일부. 빼고 싶으면 사람이 모든 쪽 보기에서 뺀다.
- **순서 바뀐 쪽은 자동(사용자 결정):** 거리·차이 기준이 엔진이 보통 짝을 "자신 있다" 고 보는 기준과 같다(0.35 이하·0.08 이상).
  엔진(`page_match`)은 건드리지 않는다 — Sleek 이 사람 없이 직접 부른다(`tests/test_sleek_engine_contract.py`).
- **판정을 바꿀 때는 `tools/check_reorder.py` 표를 비교한다.** 조용히 틀린 짝이 하나라도 나오면 실패로 끝나게 해 두었다.
- **사례는 이 PC 에만, 지문과 짝만.** 파일 이름에 필기한 사람 이름이 있다(제3자 개인정보). 배포 웹은 `RIFFLE_INSTANCE` 가
  `local-web` 이 아니면 남기지 않는다.
- **버그 리포트·데이터: 서비스 제공자 입장에서 합법의 틀 안에서 최대한(사용자 결정)**, 받는 곳은 GitHub 이슈(서버 중계). 세 층
  (알리고 기본 수집 / 사용자가 누르는 리포트 / 모으지 않음)은 명세 `2026-09-25-02`. 법 조항은 Claude 가 아는 범위 — **법률 자문 아님.**
- **LLM 이 고친 것은 사람이 합친다.** 통과 기준은 LLM 이 못 고치는 자리에(채점을 느슨하게 해 점수를 올릴 수 있다).

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| "앞뒤로 짝지어진 두 쪽 사이의 틈"만 보는 짝 후보 규칙 | 실측에서 두 쪽 모두 틈 밖에 짝이 있었다 |
| 짝 후보를 자동으로 짝짓지 않기(명세 원안) | 뒤집음 — 전제("생김새가 달라 자신 없다")가 틀렸다. 사용자 결정으로 자신 있으면 자동 |
| 짝 후보 기준 0.35 → 0.7 | 빠진 쪽에 엉뚱한 후보를 20번 중 5번 |
| 경쟁자를 "지금 짝보다 이 쪽을 더 원하는 옛 쪽"으로 좁히기 | 조용히 틀린 짝 1건 |
| 격자 전용 작은 그림 입구 | 측정해 보니 필요 없음(첫 그림 0.8초) |
| 백그라운드로 몰래 수집 | 사용자는 "합법 안에서 최대한" 을 골랐다 — 알리고 끌 수 있게 기본 수집, 개인정보·파일 원본은 동의 때만 |
| 리포트를 GitHub 이슈 작성 화면으로 열기 / 파일로 전달 | 계정 필요·공개 저장소·길이 제한 / 자동 처리 불가 |
| 판정 스스로 고치기를 지금 만들기 | 먹일 데이터가 없다 — 고친 사례 20건이 조건 |

(계속 유효한 항목은 모두 명세 두 개의 「고려했다가 안 한 것」에 있다. 이번에 격자 전용 그림·사례 기록 범위 두 줄을 더했다.)

## 미해결 질문 / 블로커

- **푸시 보류(가장 중요, 사용자 할 일).** 옛 Render 서비스 `noteditor` 가 `main` 을 따라 자동 배포된다. Render 대시보드에서 그 서비스의
  배포 가지를 `noteditor-1.2` 로 바꾼 뒤에 `git push origin main`. 로그인이 필요해 Claude 가 못 한다. 그 전까지 **이 인계 문서와
  30커밋은 이 PC 에만 있다.**
- **커밋 안 된 사용자 쪽 변경 세 파일**(`README.md`, `riffle/version.py`, `tests/test_version.py`) — 이번 세션이 만든 것이 아니다. 지난
  인계부터 "커밋할지 물을 것" 으로 남아 있다. 이 때문에 **README 에 오늘 기능(합집합·순서 바뀜·모든 쪽 보기)을 못 적었다.**
- 단위 5: 태블릿에서 결과를 끝 쪽까지 열기, 데스크톱 창에 실제로 끌어다 놓기 — 사람만 할 수 있다(미확인).
- `←` 직후 늦게 도착한 미리보기 요청이 서버 기록에 오류로 가끔 남는다(화면엔 영향 없음). 원인은 이미 보낸 요청이 비운 서버에 닿는 것.
- 명세 `2026-09-25-02` 열린 질문 넷(받는 저장소 이름·사용 데이터 기본값·사례 크기·devkit 루프가 다른 저장소 이슈를 읽는 법).
- 후보 카드("같은 쪽일까요?")가 뜨는 **실제** 파일 쌍은 아직 없다 — 만든 PDF 로만 확인했다.

## 다음 단계

1. 사용자: Render 대시보드에서 `noteditor` 배포 가지를 `noteditor-1.2` 로 → 알려 주면 `git push origin main`.
2. 사용자: 세 파일 커밋 여부 결정 → 커밋하면 `README.md` 「필기 옮기기」 절에 합집합·순서 바뀐 쪽·`봐야 할 쪽/모든 쪽` 을 한 줄씩.
3. 사용자: 실제 강의로 옮겨 보기(단위 5) — 저장한 `.sdocx` 를 태블릿에서 끝 쪽까지. "됐다" 면 명세 `2026-09-25-01` 상태를 `완료` 로.
4. 새 Render 서비스 `riffle` 이 열리면 명세 `2026-09-25-02` 단위 1(처리방침 초안 — 사람 확인)부터.
5. 사례가 쌓이면 가끔 `python tools/check_reorder.py --cases` — 고친 사례 20건이면 백로그 「판정 스스로 고치기」 명세.
