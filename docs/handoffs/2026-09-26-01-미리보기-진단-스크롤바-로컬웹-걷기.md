## 내린 결정과 근거

- **로컬 웹을 걷고 두 갈래(데스크톱·원격 웹).** 같은 일을 하는 입구가 셋이면 무엇을 쓸지부터 고르게 된다(원칙 4·8). PWA 로
  일원화하지 않은 까닭은 명세 변경 이력: 로컬 PWA 는 서버 실행기가 남고, 원격 PWA 는 필기 파일을 인터넷으로 올리며, 둘 다 파일 경로를
  몰라 저장 위치 고르기·폴더 열기·파일 받아 열기를 잃는다.
- **사용 안내서의 「창이 안 열릴 때 → 로컬 웹」 대안**은 「다시 실행, 계속되면 `%LOCALAPPDATA%\Riffle\app.log` 를 보내 달라」로 바꿨다.
  원격 웹(새 Render 서비스 `riffle`)이 열리면 그 주소를 대안으로 적을 수 있다.
- **빈 쪽을 본뜰 때 펜 캐시 참조를 걷는다.** 남기면 새 빈 쪽에 원래 쪽의 필기 그림이 비칠 수 있다(원칙 5). 실제 빈 쪽 구조와 같게 맞췄다.
- **README 는 사용자 수정과 섞지 않는다.** 커밋된 판에 같은 수정을 적용해 인덱스에만 올렸다(`git hash-object --no-filters` —
  `core.autocrlf` 가 CRLF 를 LF 로 바꿔 파일 전체가 바뀐 것으로 잡힌 한 번의 실수를 되돌리고 다시 함).

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| PWA 로 일원화 | 서버 실행기가 남거나(로컬) 필기 파일을 인터넷에 올려야 하고(원격), 파일 경로를 몰라 저장·폴더 열기·파일 받아 열기를 잃는다 |
| 로컬 웹을 남겨 「창이 안 열릴 때」 대안으로 | 사용자 결정으로 두 갈래. 대안은 앱 기록 보내기·원격 웹 |
| 빈 쪽이 없으면 새로 생긴 쪽을 만들지 않고 저장 거절 | 사람이 짝을 바꾸면 흔히 생기는 상황이다 — 저장이 멈추면 고친 것을 잃는다(원칙 7) |
| 빈 쪽 본뜨기에서 펜 캐시 참조를 남기기 | 원래 쪽의 필기 그림이 새 빈 쪽에 비칠 위험 |
| README 를 사용자 수정째 커밋 | 사용자 결정 대기 중인 수정이다 |
| 원격에 푸시 | Render 블로커 그대로 |

(계속 유효한 것은 명세 `2026-09-25-03` 변경 이력에 적었다.)

## 미해결 질문 / 블로커

- **푸시 보류(사용자 할 일, 가장 중요).** Render 대시보드에서 옛 서비스 `noteditor` 의 배포 가지를 `noteditor-1.2` 로 바꾼 뒤
  `git push origin main`. 로그인이 필요해 Claude 가 못 한다. 그 전까지 이 인계와 41커밋은 이 PC 에만 있다.
- **미리보기 문제 재현 안 됨.** 사용자가 본 창 번호(`tools/open_cases.py` 1~10)·옛 쪽·새 쪽·누른 순서를 알려 주면 그대로 재현한다.
  의심만 남은 것: 창 10개를 동시에 띄워 미리보기 응답이 늦었을 가능성(그동안 새 쪽 자리는 빈 틀로 보인다) — 미확인.
- 커밋 안 된 세 파일(`README.md` 두 줄·`riffle/version.py`·`tests/test_version.py`) — 사용자 결정 대기.
- 지난 인계의 나머지 그대로: Goodnotes 5 샘플(단위 7), 태블릿 확인(단위 8, 합친 쪽·옮긴 획·**본떠 만든 빈 쪽**이 Samsung Notes 에서
  열리는지 포함), 칸 손필기 옮기기의 실제 파일 확인, 새 Render 서비스.

## 다음 단계

1. 사용자: Render 에서 `noteditor` 배포 가지를 `noteditor-1.2` 로 → 알려 주면 `git push origin main`.

   `scratchpad` 대신 `tools/check_review_screen.py` 에 그 흐름(옛 쪽 → `다른 쪽` → 새 쪽 → 미리보기 획 수)을 더해 고정한다.
