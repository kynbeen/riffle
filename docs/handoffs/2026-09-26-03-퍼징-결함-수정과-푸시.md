## 현재 상태

2026-09-25~26 의 Sleek 필기본 갱신·공통 필기 층·연결 보기 작업과 그 뒤 진단·퍼징 수정이 모두 `main` 에 있고, 사용자가 옛 Render
서비스 `noteditor` 의 배포 가지를 `noteditor-1.2` 로 바꿔 **이 인계와 함께 `main` 을 원격에 올렸다**(블로커 해소). 전체 시험 Python 251
통과. 남은 것은 사람만 할 수 있는 확인(태블릿, Goodnotes 5 샘플)과 새 Render 서비스 `riffle` 열기, 커밋 안 된 사용자 쪽 세 파일 결정이다.

## 이번 세션에 한 일

- 사용자 요청 "W 있는 테스트 창의 다른 경우도 괜찮은가 + 이상한 입력으로 예상과 다른 결과 찾기":
  - 합성 경우 창 1·2 의 손필기 있는 옛 쪽 × 모든 새 쪽 96조합 — 획 사라짐·쪽 밖·겹침 0.
  - **퍼징**(일부러 이상한 입력을 대량으로 넣어 보는 시험) 도구 `tools/fuzz/`(Samsung Notes `fuzz.py`, Notewise `fuzz_nw.py`, 극단 입력
    `edges.py`)를 만들어 돌림. 찾아 고친 결함 넷(`15b9cc7`):
    1. 강의록 가운데에서 칸·아래로 크게 삐져나간 획이 칸 없는·더 짧은 새 쪽에서 쪽 밖 → 배치 뒤 쪽 밖 객체를 쪽 안으로 최소한 밀어 넣음
       (쪽보다 크면 줄여서, 가장자리 6px 안쪽).
    2. 빈자리 격자가 쪽보다 한 칸 커 쪽 끝 덩이가 3pt 밖 → 격자를 쪽 안에서만.
    3. 맨 뒤 쪽을 뺀 저장에서 "새 PDF 통째로 넣기" 지름길이 끼어들어 배경 쪽이 남음(Notewise 저장 거절, Samsung Notes 는 안 쓰는 PDF 쪽,
       Goodnotes 도 같은 지름길) → 결과 쪽 수가 새 PDF 쪽 수와 같을 때만.
    4. 옛 쪽째 남기는 필기본 쪽에 "칸 손필기 옮김" 카드 → "새 PDF 에 없는 쪽".
  - 고친 뒤 Samsung Notes 150·Notewise 90 무작위 경우 문제 0, 극단 입력 8가지 모두 획 수 그대로·쪽 밖 0, 실제 샘플 5쌍 결과 그대로.
  - 회귀 시험 2개 추가(큰 획 삐져나감, 맨 뒤 쪽 빼기).
- 앞선 같은 날 작업(인계 `2026-09-26-01`·`-02` 참고): 미리보기 진단, 모든 쪽 필기 노트 저장 결함, Sleek 스크롤바, 로컬 웹 걷기,
  필기본 → 일반 PDF 칸 손필기 쪽 밖 결함.
- 사용자: Render 배포 가지 전환 완료 → 백로그 체크, `main` 푸시.

## 내린 결정과 근거

- **쪽 밖 획은 쪽 안으로 밀어 넣는다(모든 형식·모든 경우).** 쪽 밖 획은 보이지도 편집되지도 않아 잃은 것과 같다(원칙 7). 최소 이동이라
  강의록과의 관계를 가장 적게 흐트러뜨린다. 가장자리 6px 안쪽을 겨누는 까닭: Samsung Notes 는 점 간격을 1/32px 로 반올림해 적어, 점이
  많은 획을 줄이면 반올림이 쌓여 끝이 몇 px 밀린다(퍼징 실측 3px).
- **새 PDF 통째로 넣기 지름길은 쪽 수까지 같을 때만.** 번호 순서만 보면 뒤 쪽을 뺀 경우를 못 가른다.
- **90도 돌린 같은 강의록이 일부만 짝지어지는 것은 기록만.** 쪽 비교가 돌아간 그림으로 이뤄지기 때문 — 드문 경우이고 손필기는 옛 쪽째 남아
  잃지 않는다.

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 쪽 밖 획을 잘라 버리기 | 한 획도 버리지 않는다(원칙 7) |
| 쪽 밖 획이 있으면 쪽을 넓히기 | 결과 쪽 모양이 새 PDF 와 달라진다 |
| 90도 돌린 쪽을 돌려서 비교 | 드문 경우 — 사용자가 원하면 착수 |
| Goodnotes 퍼징 | 합성 저널(tpl 획 블록) 만들기가 커서 공통 층 부품 시험만 |
