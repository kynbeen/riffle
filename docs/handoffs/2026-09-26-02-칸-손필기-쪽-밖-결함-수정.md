# 칸 손필기가 쪽 밖에 놓이던 결함 수정

**날짜:** 2026-09-26
**기기:** LAPTOP
**관련 명세:** `docs/specs/2026-09-25-03-Sleek-갱신과-연결-보기.md`(진행 중 — 단위 7·8 남음)

## 현재 상태

직전 인계(`2026-09-26-01`)에서 「재현 안 됨」으로 남긴 미리보기 문제의 원인을 사용자 설명으로 찾아 고쳤다(`f9718c4`). 전체 시험
Python 249·화면 node 35 통과, 브라우저에서 합성 경우 창 2 흐름을 눌러 옮긴 쪽에 손필기가 보이는 것을 확인했다. **로컬 `main` 은
원격보다 43커밋 앞서 있고(이 인계 포함) 푸시하지 않았다** — Render 블로커 그대로. 커밋 안 된 사용자 쪽 세 파일도 그대로다.

## 이번 세션에 한 일

- 사용자 설명: 테스트 창 중 "W" 가 뜨는 창에서 확인 필요 쪽을 다른 쪽에 연결하면 W 가 옮겨져 안 보인다. "W" 는
  `tools/open_cases.py` 의 합성 손글씨(지그재그 획)다.
- 진단: 창 2(합성 필기본 → 일반 PDF)의 확인 카드는 **필기 칸 위** 손필기다. 새 쪽에 칸이 없는데 원래 좌표 그대로 옮겨 새 캔버스
  밖(x 1963 > 폭 1848)에 놓였다 — 미리보기에 안 보이고 **저장 결과에서도 쪽 밖**(태블릿에서 볼 수 없음). 기계 짝이든 사람이 고른
  짝이든 같다. 창 1(필기본 → 필기본)의 카드 쪽 W 는 강의록 위라 정상이었다.
- 수정(`riffle/page_ink.py`): 새 쪽이 필기본이 아니면 쪽 전체를 강의록 영역으로 보고 칸 손필기를 그 빈자리(글·그림·강의록 손필기를
  피함)로 옮긴다. 옮기기는 옛 쪽이 필기본일 때만 일하므로 세 형식의 호출하는 곳은 늘 켠다. 카드 `panel_ink` 문구를 "필기 칸에 쓴
  손필기를 옮겼습니다 — 새 PDF 에는 칸이 없어 빈자리로" 로 바꿨다. 시험 `test_panel_handwriting_lands_inside_a_plain_new_page`.
- 명세 변경 이력에 원인과 수정 기록.

## 내린 결정과 근거

- **칸 없는 새 쪽에서는 강의록의 빈자리로.** 쪽 밖에 두면 손필기를 잃는 것과 같다(원칙 7). 사용자가 앞서 정한 "여백이 모자라면
  강의록 빈칸으로" 와 같은 규칙이다. 원래 칸에 가장 가까운 쪽(대개 오른쪽)의 빈자리가 고른다.
- **여전히 카드로 묻는다.** 칸 손필기를 강의록 위로 옮긴 것이라 사람이 한 번 보는 것이 맞다(원칙 3).

## 고려했다가 안 한 것

| 대안 | 왜 안 했나 |
|---|---|
| 칸 없는 새 쪽을 칸만큼 넓혀 쪽 밖 손필기를 담기 | 결과 쪽 모양이 새 PDF 와 달라진다 — 새 PDF 가 정답이라는 원칙과 어긋난다 |
| 칸 손필기를 따로 쪽 하나로 모으기 | 그 쪽 강의 내용과 떨어져 뜻을 잃는다 |
| 카드를 없애고 조용히 옮기기 | 칸 글과 함께 있던 필기를 슬라이드 위로 옮긴 것이다 — 한 번은 사람이 본다 |
